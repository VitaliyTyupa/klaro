# Spec Delta

## Purpose

Забезпечити спільну поведінку ручного текстового редактора у вузькій панелі та вебзастосунку з контрольованим обсягом і тимчасовими даними.

## ADDED Requirements

### Requirement: Manual editor and bounded input
Система SHALL приймати лише текст, вручну введений або вставлений у власний редактор. Панель SHALL приймати до 5000 Unicode code points включно; вебредактор SHALL мати явно показану більшу межу. Клієнт і сервер SHALL однаково перевіряти межі без мовчазного обрізання. Завеликий текст SHALL залишатися доступним для редагування без надсилання.

#### Scenario: Panel limit exceeded
- **WHEN** користувач вставляє 5001 символ за визначеним правилом підрахунку
- **THEN** текст не надсилається, інтерфейс показує перевищення й посилання на вебредактор без автоматичного перенесення тексту

### Requirement: Selection scoped processing
Система SHALL обробляти виділення у власному редакторі, якщо воно є, і весь вхідний текст за відсутності виділення. Решта тексту SHALL бути лише явно позначеним контекстом у межах дозволеного обсягу, а не частиною результату заміни. Вхідний текст SHALL не змінюватися через отримання результату.

#### Scenario: Selected sentence
- **WHEN** користувач запускає обробку виділеного речення в редакторі Klaro
- **THEN** результат стосується лише цього речення, сусідні речення не замінюються

### Requirement: Controlled execution and revision safety
Система SHALL підтримувати явний запуск та керовану користувачем автоматичну перевірку після паузи вводу. Автоматичний режим SHALL бути вимкнений до його ввімкнення користувачем, діяти лише у відкритому активному робочому просторі та не запускати запити для порожнього або незміненого вводу. Результат SHALL прив'язуватися до ревізії тексту, виділення, режиму й налаштувань.

#### Scenario: Stale response
- **WHEN** відповідь для попередньої ревізії надходить після редагування тексту
- **THEN** вона не замінює актуальний результат і не запускає похідні запити для нової ревізії

#### Scenario: Pause automatic processing
- **WHEN** користувач вимикає автоматичний режим або закриває робочий простір
- **THEN** відкладені запуски скасовуються й нові автоматичні запити не надсилаються

### Requirement: Copy and temporary draft recovery
Система SHALL надавати копіювання основного результату без запису в сторонні поля. Для зворотного перекладу SHALL не бути окремої кнопки копіювання. Система SHALL зберігати обмежений список оригіналів оброблених чернеток лише в поточній сесії редактора, дозволяти їх відновлення та очищати його при завершенні сесії, виході з акаунта або явному очищенні.

#### Scenario: Recover original
- **WHEN** користувач обирає попередній оригінал у межах поточної сесії
- **THEN** він відновлюється у вхідному полі як нова ревізія без автоматичного застосування старих результатів

#### Scenario: Clipboard failure
- **WHEN** браузер не дозволяє запис у буфер обміну
- **THEN** результат залишається виділюваним для ручного копіювання та показується зрозуміле повідомлення

### Requirement: Accessible result presentation
Редактор SHALL дозволяти керування клавіатурою, мати підписи полів, видимий фокус, доступні назви дій і текстові позначки правок незалежно від кольору. Асинхронні оновлення SHALL не перехоплювати фокус.

#### Scenario: Keyboard review
- **WHEN** користувач переглядає правки й розгортає розділи лише клавіатурою
- **THEN** усі дії доступні, стани озвучуються допоміжними засобами й фокус залишається передбачуваним
