# Correction vertical slice: перевірки

Task 6.1: `npm test`, `npm run test:editor-ui`, `npm run test:operations` і `npm run test:language-regression` пройшли. Chrome **154.0.8037.57** перевірив захист selection, передачу spans, незмінний input, no-changes presentation, primary / native results і accessibility. REST/socket workflow перевірено на локальних PostgreSQL / Redis з deterministic provider double.

Default synthetic policy — `double-policy-v3`, prompt `language-v3`. Versioned prompt додає мінімальні spelling / grammar / punctuation / word-order / natural-wording edits, ambiguity warning, names / commitment preservation, no-changes та canonical grouped replacement. Старі prompt versions залишаються підтримуваними. Зміна prompt не активує OpenAI: paid policy потребує власного evaluation report і human review для точної model / prompt version.

Для recommendation actions у task 6.4 створено наступну policy `double-policy-v4` / `language-v4`, яка є поточним synthetic default; v3 зберігає свою поведінку. V4 уточнює явне paraphrase / alternatives / explanation і передає recommendation snapshot для порівняння з original. Це не активація paid model.

У task 7.3 поточний synthetic default оновлено до v5 із translation fidelity rules; historical v3 / v4 behaviors зберігаються. Деталі в [translation verification](translation-verification.md).

Protected spans живуть лише в editor memory, включаються у command і очищаються після зміни input / restore / clear. Task передає selected original та відносні UTF-16 protected offsets. Validator відхиляє редагування або insertion усередині захищеної позиції, навіть якщо та сама фраза збереглася деінде. Numeric digit groups для correction v3 не можуть довільно змінюватися; це консервативна structural перевірка, не доказ збереження змісту.

12 синтетичних `uk/de/en/vi` fixtures пройшли contract / identity checks із numbers, negation, commitment, style і protected terms. [Звіт](evaluations/double-regression.json) явно містить `realModelEvaluation: false`, `languageReadiness: unreviewed` і pending human review. Реальна grammar / semantic якість залишається release gate task 11.1.

Tasks 6.2–6.3: `tests/edit-review.test.mjs`, `tests/native-rendering.test.mjs`, `tests/result-validation.test.mjs`, browser keyboard / axe checks і `npm run test:recovery` пройшли. Незалежні групи відновлюються з початкового original; залежні logical changes подаються одним canonical replacement, а перекривні spans відхиляються. Review не змінює input / input revision, створює новий recommendation ID і відхиляє obsolete primary / native responses.

Initial correction має два bounded backend stages. Native failure зберігає primary, copy action і явний retry тільки `back-translation`; retry не повторює correction. Review автоматично надсилає лише актуальну recommendation для native rendering, скасовуючи попередню. Browser test перевіряє partial failure, keyboard retry / reject / accept і оновлення третьої області без зміни input. Native result не має copy action і містить застереження про можливі помилки перекладу. Unit tests перевіряють відсутність feedback loop й ігнорування late results.

Task 6.4: unit / browser / REST integration checks пройшли. Alternatives generation має один backend stage і до трьох distinct IDs; список не змінює primary до explicit selection. Dropdown selection запускає один native operation для selected text. Switch скасовує попередній запит; late response не замінює актуальні primary / native results. Paraphrase — окрема кнопка та operation, з preference snapshot і двома fixed stages. Input залишається незмінним.

Task 6.5: explicit explanation unit tests і keyboard / axe browser checks пройшли. Пояснення має окремий state, не замінює primary або native rendering. Command містить selected original, current recommendation text / ID та target native language; v4 provider input передає обидва тексти для порівняння. Немає automatic explanation call; review робить попередній текст неактуальним, а late response для старого recommendation ID відхиляється. Окремий explanation provider attempt врахований REST integration usage test.

Task 6.6: `npm run test:correction-e2e` пройшов у Chrome **154.0.8037.57**. Test завантажує packaged MV3 extension і взаємодіє зі справжнім side-panel document через CDP. Native `identity.launchWebAuthFlow` та web cookie login використовують локальний signed OIDC provider; обидві surfaces належать одному synthetic account. Реальний backend / PostgreSQL / Redis із provider double виконують input → correction → native rendering → native clipboard write. Input зберігається, native rendering не має copy action, кожна correction має рівно два attempts.

Socket примусово розривається під час operation; reconnect і snapshot відновлюють результат без другого acceptance POST або додаткового provider attempt. User quota refusal зберігає draft і не запускає provider. Logout відкликає обидві sessions та очищає editor / storage. Закриття native panel з pending debounce і повторне відкриття дають порожній editor, новий login та жоден hidden operation. Сторонній synthetic page canary не потрапляє до payload, а packaged extension не має page-read permissions. Усі дані тестові; це не real-model language evaluation.
