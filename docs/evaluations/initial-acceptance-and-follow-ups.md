# Початкове прийняття та подальші покращення

## Рішення користувача — 2026-10-13

Користувач вважає поточний результат прийнятним для початку розробки й використання першої версії. Невирішені зауваження переносимо до подальших покращень, без заміни моделі або ускладнення правил оцінювання зараз.

Прості правила роботи:

- Якщо правок немає, повертаємо оригінальне речення без змін.
- За явною дією «Ще варіанти» отримуємо щонайбільше три альтернативи та показуємо їх по черзі. Повторні натискання перебирають отриманий набір; після останнього варіанта дія недоступна. Нова ревізія тексту або налаштувань дозволяє новий набір.
- Мовне оцінювання автоматичне; ручний розбір потрібен лише для спірних випадків. Feedback після отримання результату добровільний, передає категорію оцінки та ідентифікатор операції без тексту користувача.

Прийняття користувачем зафіксоване окремо від машинної оцінки. Воно не переписує evidence, не оголошує всі перевірки успішними й саме по собі не активує production policy або публікацію в магазинах.

За наступним дорученням користувача прийняття відображено в механізмі активації: окремий `initial-acceptance-v1` record дозволяє завантаження policy зі збереженням фактичних відхилень. Підготовлені конфігурація та інструкції описані в [документі активації](production-policy-activation.md). Сервер і платна обробка цим export не запускаються.

## Збережені результати

[Початковий прогін](openai-run-v1.json): 72 команди, 80 викликів, 63 технічно прийнятні відповіді, 17 відхилених; 16 похідних етапів не виконано. Вартість — $0.032204.

[Автоматичний суддя](openai-judge-v1.json), [зручний звіт](openai-judge-v1.html): 12/12 калібрувальних прикладів, 74 мовні оцінки pass, 6 fail, вартість — $0.115578. Успіх цієї калібровки не підтверджує правильність кожного пояснення судді. Машинний gate залишився непрохідним; індивідуальні ручні рішення у звіт не внесені.

## Зауваження для подальшої розробки

| Область | Що врахувати |
| --- | --- |
| Видимість контексту | Показувати контекст біля речення. У `de-grammar` уточнено, що `Sie` означає одну жінку: потрібне `hat`, хоча без контексту `Sie haben …` правильне. |
| Пояснення судді | Суддя помилково запропонував малу літеру на початку `Sie …`. У `en-style` вимагав переписати правильне речення з додаванням непідтвердженого контексту. Незмінене правильне речення є прийнятним результатом. |
| Збереження точності | Перевірити `alternatives-uk-formal`, `alternatives-en-neutral`, `alternatives-en-formal`: окремі варіанти втрачали «рівно» або додавали «орієнтовно». Інші оцінки судді залишаються предметом подальшого розбору. |
| Мовна помилка | У `source-uk` отримано `надіране` замість `надіслане`. |
| Службові дані | Порожні `recommendationId` спричинили технічні відхилення навіть за читабельного тексту. Розглянути формування ідентифікаторів застосунком. |
| Позиції правок | Частина відповідей мала неправильні межі фрагментів або не відтворювала заявлений результат застосуванням правок. Зберегти перевірку перед застосуванням до тексту. |
| Межі валідаторів | Нульова довжина фрагмента для вставки та заміна `3` на `три` потребують розбору: технічне відхилення не завжди означає мовну помилку. |
| Походження довідки | `lexical-en` повернув неправильний `originKind` для згенерованого доповнення. |
| Подальші перевірки | Після відповідних виправлень перевірити пропущені похідні етапи та спірні приклади. Новий платний прогін потребує окремо погодженого бюджету. |

Цей список є робочим backlog, а не новим обов'язковим переліком ручного review кожної відповіді. Незавершені перевірки магазинів, приватності та фінального acceptance залишаються окремими release-задачами.
